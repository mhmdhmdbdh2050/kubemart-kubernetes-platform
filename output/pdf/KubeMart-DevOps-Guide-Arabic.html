الفصل 1 — نظرة عامة

KubeMart مشروع تعليمي يربط متجرًا بسيطًا بواجهة API وقاعدة بيانات، ويستخدم Kubernetes لتجربة النشر والتوجيه والتخزين والأمان والمراقبة.

ما الذي يفعله التطبيق؟

واجهة HTML/CSS/JavaScript تعرض كتالوجًا وسلة، وتتيح تسجيل الحساب وطلب إنشاء order. FastAPI يتحقق من الحساب والجلسة، ويقرأ الأسعار والمخزون من PostgreSQL، ثم ينشئ الطلب ويخصم الكميات ضمن transaction. لا توجد بوابة دفع أو شحن أو إدارة مخزون تجارية متكاملة.

الفصل 2 — العمارة وتدفق الطلب

مخطط التطبيق

المخطط لا يثبت وجود موارد حية في الكلاستر. Controller يقرأ Ingress ثم يوجه إلى الواجهة.

تدفق تحميل المتجر

  1. DNS يحل اسم نطاق يملكه المشغل إلى نقطة دخول Ingress.
  2. Ingress controller يقرأ host/path وTLS في kubemart-ingress.yaml.
  3. Ingress يرسل إلى frontend Service port 80، التي تختار Pods بوسم app=frontend.
  4. Service targetPort 8080 يوصل إلى NGINX الذي يخدم index.html.
  5. JavaScript يطلب /api/products. NGINX يمررها إلى API Service :8000، وFastAPI يستعلم PostgreSQL.

تدفق الحساب والطلب

POST /api/auth/register {customer_name,email,password} FastAPI validates -> Argon2 hash -> PostgreSQL users random token -> HttpOnly/Secure/SameSite=Strict cookie sessions table stores SHA-256(token), expiry 7 days POST /api/orders {items:[{product_id,quantity}]} verify hashed cookie/session -> SELECT products FOR UPDATE validate stock + calculate total on server insert order/items + decrement stock in one transaction

الفصل 4 — الإعداد والنشر

التكلفة: EC2/EBS/Load Balancer/NAT/Monitoring قد تكلف مالًا. استخدم sandbox، وافهم التكاليف والصلاحيات. لا تحذف PVC قبل حفظ البيانات.

المتطلبات

Kubernetes وkubectl، ingress-nginx، DNS/TLS، EBS CSI driver/IAM، Docker/ECR/AWS CLI. إنشاء AWS network/cluster غير موجود بالمستودع.

1. الفحص والتنزيل

git clone https://github.com/mhmdhmdbdh2050/kubemart-kubernetes-platform.git cd kubemart-kubernetes-platform kubectl config current-context kubectl cluster-info kubectl get nodes -o wide kubectl get storageclass

تأكد من context المقصود وحالة العقد. هذه أوامر قراءة.

2. Namespace وSecrets

kubectl apply -f k8s/namespace/namespace.yaml kubectl create secret generic postgres-secret -n kubemart \ --from-literal=POSTGRES_DB='kubemart' \ --from-literal=POSTGRES_USER='kubemart_app' \ --from-literal=POSTGRES_PASSWORD='REPLACE_WITH_LONG_RANDOM_VALUE' # after receiving certificate for your domain kubectl create secret tls kubemart-tls -n kubemart \ --cert=/path/to/fullchain.pem --key=/path/to/private-key.pem

قيم توضيحية فقط. استخدم secret manager وتشفير at-rest وRBAC؛ Base64 ليس تشفيرًا. لا تحفظ ملف Secret حقيقي في Git.

3. بناء الصور إلى ECR

REGISTRY=YOUR_AWS_ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin "$REGISTRY" docker build -f app/backend/Dockerfile -t "$REGISTRY/kubemart-api:v3" app/backend docker push "$REGISTRY/kubemart-api:v3" docker build -f app/frontend/Dockerfile -t "$REGISTRY/kubemart-frontend:v1" app/frontend docker push "$REGISTRY/kubemart-frontend:v1"

استبدل YOUR_AWS_ACCOUNT_ID برقم حساب AWS الخاص بك، وتأكد من ملكية registry/repositories/tag. الإعداد يشير إلى Secret ecr-pull-secret أو اعتمد هوية عقدة. استخدم tags فريدة وimage digests.

4. قاعدة البيانات

kubectl apply -f k8s/storage/kubemart-storageclass.yaml kubectl apply -f k8s/storage/postgres-pvc.yaml kubectl apply -f k8s/services/postgres-service.yaml kubectl apply -f k8s/statefulsets/postgres-statefulset.yaml kubectl rollout status statefulset/postgres -n kubemart kubectl get pvc,pv -n kubemart

WaitForFirstConsumer يؤخر الربط لحين معرفة جدولة Pod. PVC Pending قد يعني driver/IAM/AZ.

5. API والواجهة والشبكة

kubectl apply -f k8s/app/backend.yaml kubectl apply -f k8s/deployments/frontend-deployment.yaml kubectl apply -f k8s/services/frontend-service.yaml kubectl apply -f k8s/security/network-policy-example.yaml kubectl apply -f k8s/security/api-ingress-policy.yaml kubectl apply -f k8s/security/postgres-ingress-policy.yaml kubectl apply -f k8s/ingress/kubemart-ingress.yaml kubectl rollout status deployment/kubemart-api -n kubemart kubectl rollout status deployment/frontend -n kubemart

استبدل host؛ جهز TLS وECR credentials؛ أثبت دعم NetworkPolicy في CNI. HPA والمراقبة لها متطلبات تثبيت منفصلة.

6. التحقق

kubectl get pods,svc,ingress,pvc -n kubemart -o wide kubectl get endpointslices -n kubemart kubectl get events -n kubemart --sort-by=.metadata.creationTimestamp kubectl logs deployment/kubemart-api -n kubemart curl -I https://YOUR_DOMAIN/ curl https://YOUR_DOMAIN/api/products

المتوقع: Pods Ready وendpoints موجودة وPVC Bound وTLS صالح وJSON منتجات. لم تنفذ هذه الأوامر على كلاستر المستخدم؛ هذه نتائج متوقعة فقط.

تنظيف

راجع الكلفة والبيانات أولًا. إيقاف CronJob لا يعني حذف PVC؛ لا تحذف namespace إلا بعد تأكيد أن بيانات DB قابلة للتخلص.

الفصل 5 — شرح تقني عميق

Image وContainer

Dockerfile يحدد base image والملفات والـuser والـcommand؛ image قالب والحاوية نسخة تشغيل. Backend على Python 3.12-slim وUID 10001؛ NGINX unprivileged على 8080. Kubernetes يسحب الصور ولا يبنيها.

Service وIngress

Service يختار Pods عبر labels ويقدم DNS ثابتًا. EndpointSlices تعرض الأهداف الجاهزة. Ingress Controller يطبق قواعد Ingress؛ وجود المورد لا ينشئ DNS/TLS أو public load balancer.

التخزين

PostgreSQL StatefulSet نسخة واحدة مع PVC 5Gi. Retain يقلل الحذف الآلي للقرص، لكنه ليس backup ولا يثبت الاستعادة. يلزم backup منفصل وتجربة restore.

الجلسات

  1. التسجيل يتحقق EmailStr وكلمة مرور 12-128 حرفًا.
  2. Argon2 hash يذهب لusers.
  3. token عشوائي في Cookie؛ PostgreSQL تحفظ SHA-256 digest وانتهاء الجلسة.
  4. كل /api/auth/me وPOST orders يتحقق من session غير منتهية؛ logout يحذفها.
  5. لا reset password أو verification أو refresh rotation.

المخزون والمعاملة

API يجمع الكميات، يقفل صفوف المنتجات بـFOR UPDATE بترتيب IDs، يتحقق من stock ويحسب السعر من DB ثم يدرج order/items ويخصم المخزون ضمن transaction. هذا يقلل oversell؛ لا يمنع retry من إنشاء طلب ثان (لا idempotency key).

Health probes

Probeالمسارالمعنى
API liveness/liveالتطبيق يرد، لا يتصل DB.
API readiness/healthيفحص DB بـSELECT 1؛ الفشل يبعد Pod عن traffic.
frontend/يثبت NGINX/الصفحة فقط.
Postgrespg_isreadyيختبر قبول اتصال محلي لا backup.

HPA/PDB/Quota وCI

HPA CPU 60% من requests على frontend min3/max6، ويتطلب metrics API وrequests. PDB minAvailable2 يحمي من بعض الإخلاء الطوعي فقط. Quota يحد مجموع الموارد/Pods. GitHub Actions يعمل على push وpull_request؛ compile/build/Kubeconform فقط، بلا tests/scans/deploy.

الفصل 6 — فهم الإعدادات

ربط labels وports

# Pod template labels: app: frontend containerPort: 8080 # Service selector: app: frontend ports: - port: 80 targetPort: 8080 # Ingress service: name: frontend port: number: 80

اختلاف labels يؤدي إلى endpoints فارغة، واختلاف targetPort يفشل الاتصال. افحص selector وEndpointSlices والمنفذ الفعلي.

Secret injection

env: - name: POSTGRES_PASSWORD valueFrom: secretKeyRef: name: postgres-secret key: POSTGRES_PASSWORD

يوصل السر لـAPI/Postgres فقط. لا تضعه في image أو README. Secret لا يعني أن etcd مشفر تلقائيًا؛ قلل RBAC وفعل encryption at rest.

SecurityContext

runAsNonRoot: true runAsUser: 101 readOnlyRootFilesystem: true allowPrivilegeEscalation: false capabilities: drop: ["ALL"]

frontend يركب emptyDir لـcache/tmp. اختبر UID والمسارات في الصورة. backend UID 10001.

TLS وHelm

Host في rules وTLS متطابق، والـSecret في namespace kubemart ويحوي شهادة للنطاق. Values ملفات إدخال إلى chart لا موارد منشورة؛ راجع helm template ونسخة chart قبل install.

الفصل 12 — مفتاح الإجابات

الإجابات هنا فقط لتتمكن من حل الفصل السابق أولًا.
س1: ب. Service عنوان ثابت يوجه للـPods المطابقة للselector.
س2: خطأ؛ يلزم Controller وDNS وendpoints وشبكة وشهادة.
س3: Pod وحدة تشغيل؛ Deployment controller يحافظ على replicas ويدير rollout والاستبدال.
س4: ب. NGINX frontend يخدم index.html.
س5: خطأ؛ Redis مختبر مستقل، لا اتصال له في main.py.
س6: Client→Ingress Controller يطبق rule→Service→Pod؛ rule وصف لا hop.
س7: Service port 80 يوجه إلى targetPort 8080 داخل NGINX.
س8: Ingress→frontend Service→NGINX proxy→API Service 8000→FastAPI SELECT→Postgres→JSON.
س9: خطأ؛ API يحسب total من سعر DB ويتحقق من stock.
س10: Cookie HttpOnly/Secure/SameSite بالمتصفح، digest SHA-256 وexpiry في sessions.
س11: تأخير provision/bind حتى يحدد scheduler topology المناسبة للPod.
س12: Ingress/controller، frontend endpoints، NGINX upstream/logs، API endpoints/readiness/logs، policy/CNI/DNS.
س13: PVC events وCSI/IAM/AZ؛ أصلح التخزين ثم Postgres/service/secret ثم API /health.
س14: لا يمكن حساب CPU utilization جيدًا دون request؛ HPA قد لا يتصرف.
س15: خطأ؛ /live لا يفحص DB؛ /health readiness يفعل ذلك.
س16: Secure cookie لا ترسل عبر HTTP؛ افحص DevTools/HTTPS/host/path، استخدم TLS، ولا تلغ Secure علنًا.
س17: CNI لا يطبق policies أو selector/source namespace خاطئ؛ تحقق من سلوك node-local أيضًا.
س18: describe pod وevents؛ get endpointslices وget svc -o yaml.
س19: تسريب DB لا يعطي token الصريح. مناسب لtoken عشوائي عالي entropy؛ لا يحمي سرقة cookie أو شبكة دون TLS.
س20: يقفل صفوف المنتج داخل transaction؛ الطلب التالي يرى المخزون المحدث. retry قد يكرر order؛ أضف idempotency key unique.
س21: خطأ؛ PDB يحكم بعض الإخلاءات الطوعية، لا سقوط node.
س22: Retain يمنع reclamation الآلي، لا ينشئ نسخة منفصلة ولا يثبت restore/PITR.
س23: سباق DDL، لا schema history/rollback، rollout قد يفشل؛ job واحد مع locking وexpand/contract.
س24: rate limit auth، audit/alerts وتأخير/lockout، reset/verification ورسائل لا تكشف وجود الحساب.
س25: DNS/TLS/Ingress events/controller، service/endpoints، curl داخلي، NGINX logs، API readiness/logs، DB/PVC/secret والسياسات. لا restart عشوائي.
س26: managed DB أو operator، HA، backups/PITR مشفرة وrestore مجرب وRPO/RTO؛ managed أقل عبئًا وأعلى اعتمادًا/تكلفة.
س27: تحقق من CNI واختبر allow/deny في staging؛ اسمح DNS 53 وAPI→DB 5432 والخدمات المطلوبة فقط.
س28: unit/integration/E2E، scans/SBOM، digest، schema validation، secrets scan، staging smoke ثم approval قبل production وrollback.
س29: EC2/EBS/LB/NAT/data transfer/retention/replicas/CronJob؛ budgets/tags/limits وأوقف lab غير المستخدم.
س30: مفتوح. مثال: tests (CI يغطي DB/races)، policy (allow يعمل/deny يفشل)، backup restore (ضمن RTO/RPO).

الخلاصة والمراجع

KubeMart مختبر مفيد لربط web app بKubernetes. ممارسات الكود الجيدة تشمل Argon2، digest للجلسة، Cookie آمنة، حساب السعر على الخادم، قفل المخزون، وفصل liveness عن DB. أهم فجوات الإنتاج: NetworkPolicy غير مثبتة الفعالية، PostgreSQL نسخة واحدة بلا backup/restore، ولا توجد اختبارات وظيفية. الملفات تصف إعدادًا مقصودًا لا حالة cluster حية.
